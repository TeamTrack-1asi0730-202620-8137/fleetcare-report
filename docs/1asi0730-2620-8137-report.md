# **Chapter I: Introduction**
## **1.1. Startup Profile**
### **1.1.1. Startup Description**

<p style="text-align: justify;">

  TeamTrack es una startup tecnológica orientada al desarrollo de soluciones digitales para mejorar la gestión y operación de pequeñas empresas de transporte y logística. La iniciativa surge ante la necesidad de facilitar el control de flotas de carga ligera, donde la información relacionada con vehículos, kilometraje, mantenimiento e incidencias suele encontrarse dispersa o registrarse mediante procesos manuales. Como primer producto, TeamTrack desarrolla FleetCare, una plataforma enfocada en centralizar esta información y facilitar el seguimiento del estado operativo de los vehículos.

</p>

<p style="text-align: justify;">

  La propuesta de valor de TeamTrack se centra en brindar a las pequeñas empresas de transporte una herramienta que les permita gestionar sus vehículos de manera preventiva y organizada. A través de FleetCare, los jefes de flota pueden consultar el estado de sus unidades, supervisar mantenimientos, controlar el consumo de combustible y revisar incidencias reportadas. Asimismo, conductores y mecánicos pueden registrar kilometraje, completar listas de cotejo antes de iniciar una ruta y reportar fallas detectadas. De esta manera, la solución busca facilitar la detección temprana de problemas y reducir la dependencia de registros manuales o información distribuida en diferentes medios.

</p>

<p style="text-align: justify;">

  Desde una perspectiva comercial y operativa, TeamTrack plantea FleetCare bajo un modelo B2B (Business-to-Business) soportado por un esquema SaaS (Software as a Service). Este enfoque permite ofrecer a pequeñas empresas de transporte una solución accesible mediante suscripción y adaptable al crecimiento de sus flotas. A largo plazo, TeamTrack busca consolidar FleetCare como una herramienta que contribuya a reducir fallas inesperadas, mejorar la planificación del mantenimiento y proporcionar información útil para la toma de decisiones, promoviendo una gestión de flotas más preventiva, organizada y eficiente.

</p>

## **1.2. Solution Profile**
### **1.2.1 Background and Problem Statement**

<p style="text-align: justify;">

  La gestión de flotas de transporte de carga ligera representa un desafío importante para pequeñas empresas de logística que dependen diariamente de la disponibilidad y buen funcionamiento de sus vehículos. Cuando no existe un control adecuado del kilometraje, el mantenimiento preventivo y las condiciones de las unidades, pueden presentarse fallas mecánicas inesperadas durante las rutas. Estas situaciones generan interrupciones en las operaciones, retrasos en las entregas y mayores gastos asociados a reparaciones que podrían haberse prevenido mediante un seguimiento oportuno.

</p>

<p style="text-align: justify;">

  Esta problemática también tiene un impacto económico y operativo para las empresas. La falta de información centralizada sobre el estado de los vehículos dificulta determinar cuándo corresponde realizar actividades como cambios de aceite, revisión de frenos, inspecciones técnicas u otros mantenimientos preventivos. Asimismo, llevar estos controles mediante registros manuales, hojas de cálculo o información dispersa puede provocar que mantenimientos importantes sean realizados fuera del momento adecuado, incrementando el riesgo de averías y reduciendo la disponibilidad de las unidades.

</p>

<p style="text-align: justify;">

  El problema se relaciona principalmente con la falta de seguimiento continuo y organización de la información de la flota. Los jefes de flota necesitan conocer el estado general de sus vehículos, identificar próximos mantenimientos, controlar el consumo de combustible y supervisar las incidencias reportadas. Al mismo tiempo, conductores y mecánicos necesitan mecanismos sencillos para registrar información operativa como el kilometraje, completar listas de cotejo antes de iniciar una ruta y reportar fallas detectadas. Cuando esta información no se encuentra centralizada, resulta más difícil detectar problemas de manera anticipada y tomar decisiones oportunas sobre cada vehículo.

</p>

<p style="text-align: justify;">

  Frente a esta situación, FleetCare propone una plataforma SaaS orientada al monitoreo y gestión preventiva de flotas de transporte de carga ligera. La solución busca centralizar la información de los vehículos, facilitar el registro de kilometraje e incidencias, gestionar inspecciones mediante checklists y generar alertas relacionadas con próximos mantenimientos. De esta manera, se busca ayudar a las pequeñas empresas de transporte a reducir fallas inesperadas, mejorar la disponibilidad de sus unidades y contar con información que facilite la toma de decisiones sobre su flota.

</p>

<p style="text-align: justify;">

  Para definir el problema de manera estructurada, se aplicó la técnica de las 5 W's y 2 H's:

</p>

<ul style="text-align: justify;">

  <li>
    <b>Who:</b> Jefes de flota y dueños de pequeñas empresas de transporte de carga ligera, así como conductores y mecánicos responsables de la operación, inspección y mantenimiento de los vehículos.
  </li>

  <li>
    <b>What:</b> Dificultad para controlar de manera centralizada el estado de los vehículos, los mantenimientos preventivos, el kilometraje, el consumo de combustible y las fallas reportadas, incrementando el riesgo de averías inesperadas y retrasos en las operaciones.
  </li>

  <li>
    <b>Where:</b> En pequeñas empresas de transporte y logística que operan flotas de vehículos de carga ligera y requieren supervisar continuamente el estado de sus unidades.
  </li>

  <li>
    <b>When:</b> El problema se presenta durante la operación diaria de la flota, especialmente cuando no se realizan inspecciones o mantenimientos en el momento adecuado, o cuando una falla mecánica ocurre durante una ruta.
  </li>

  <li>
    <b>Why:</b> Debido a la falta de una herramienta centralizada que permita registrar y consultar información sobre los vehículos, controlar los mantenimientos preventivos y detectar oportunamente posibles problemas en las unidades.
  </li>

  <li>
    <b>How:</b> Los responsables de la flota realizan controles utilizando registros manuales, hojas de cálculo u otros medios separados. Esto dificulta mantener actualizada la información de cada vehículo y realizar un seguimiento oportuno de mantenimientos, inspecciones e incidencias.
  </li>

  <li>
    <b>How Much:</b> Las fallas no detectadas oportunamente pueden generar gastos adicionales por reparaciones, pérdida de disponibilidad de los vehículos y retrasos en las entregas, afectando la eficiencia operativa y los costos de las pequeñas empresas de transporte.
  </li>

</ul>

### **1.2.2 Lean UX Process**
#### **1.2.2.1. Lean UX Problem Statements**

<ul style="text-align: justify;">

  <li>
    <b>Context:</b> Las pequeñas empresas de transporte y logística dependen de la disponibilidad de sus vehículos de carga ligera para cumplir con sus operaciones y entregas. Para mantener la continuidad de sus actividades, necesitan controlar información como el kilometraje, el estado de los vehículos, los mantenimientos preventivos, el consumo de combustible y las incidencias detectadas durante la operación.
  </li>

  <li>
    <b>Problem observation:</b> Se ha identificado que la gestión de estas flotas suele realizarse mediante registros manuales, hojas de cálculo o información distribuida en diferentes medios. Esto dificulta que los jefes de flota conozcan oportunamente el estado de cada vehículo y planifiquen sus mantenimientos.   <li>
    <b>Impact:</b> La falta de seguimiento y mantenimiento preventivo puede ocasionar fallas mecánicas inesperadas, vehículos fuera de servicio, retrasos en las entregas y mayores gastos de reparación. Además, la información dispersa dificulta el control del consumo de combustible, la planificación de mantenimientos y la toma de decisiones por parte de los responsables de la flota, afectando la eficiencia operativa de las pequeñas empresas de transporte.

## **1.3. Target Segments**

FleetCare está dirigido a dos segmentos principales que participan directamente en la gestión y operación de pequeñas flotas de transporte de carga ligera. Esta segmentación permite concentrar el desarrollo del producto en las necesidades del jefe de flota, responsable de la gestión y supervisión de los vehículos, y del conductor, responsable de su operación diaria y del registro de información desde campo.

### **Segmento 1: Jefe de flota**

<p style="text-align: justify;">
  El primer segmento objetivo de FleetCare está conformado por jefes de flota de pequeñas empresas dedicadas al transporte y distribución de carga ligera. Estos usuarios son responsables de supervisar el funcionamiento general de la flota y asegurar que los vehículos se encuentren disponibles para cumplir con las rutas y actividades programadas. En este tipo de empresas, la información relacionada con vehículos, mantenimientos, inspecciones, incidencias, kilometraje y combustible suele encontrarse distribuida entre hojas de cálculo, documentos físicos u otros medios, dificultando su seguimiento y actualización.
</p>

<p style="text-align: justify;">
  Entre sus principales responsabilidades se encuentra administrar la información de los vehículos, supervisar su estado operativo, consultar los resultados de las inspecciones, realizar seguimiento a las incidencias reportadas y controlar los mantenimientos requeridos. Asimismo, necesita consultar información relacionada con el kilometraje y consumo de combustible para obtener una visión general del uso y desempeño de las unidades.
</p>

<p style="text-align: justify;">
  Desde una perspectiva conductual, el jefe de flota busca mantener la mayor cantidad posible de vehículos disponibles y reducir situaciones que puedan afectar las operaciones, como fallas inesperadas, incidencias pendientes o mantenimientos realizados fuera del momento adecuado. Una de sus principales dificultades es no disponer de información centralizada y actualizada que le permita conocer rápidamente la situación de cada vehículo. Por ello, valora herramientas que faciliten la supervisión de la flota y permitan consultar información histórica para apoyar la toma de decisiones.
</p>

<p style="text-align: justify;">
  En cuanto a su perfil tecnológico, el jefe de flota utiliza principalmente computadoras y dispositivos móviles para realizar actividades administrativas, revisar información y coordinar las operaciones. Debido a que FleetCare está orientado a pequeñas empresas, se considera que estos usuarios no necesariamente cuentan con personal especializado en tecnologías de información o infraestructura tecnológica avanzada. Por esta razón, la solución debe ofrecer una aplicación web intuitiva y accesible desde un navegador, evitando configuraciones complejas para realizar las principales actividades de gestión.
</p>

### **Segmento 2: Conductor**

<p style="text-align: justify;">
  El segundo segmento objetivo de FleetCare está conformado por conductores de vehículos de carga ligera. Estos usuarios participan directamente en la operación diaria de las unidades y mantienen contacto frecuente con los vehículos, por lo que pueden registrar información relevante sobre su utilización e identificar oportunamente problemas que puedan afectar su funcionamiento.
</p>

<p style="text-align: justify;">
  Entre sus principales actividades dentro de FleetCare se encuentra realizar inspecciones preoperacionales antes de iniciar una ruta, completar listas de verificación, registrar observaciones y evidencias, reportar incidencias detectadas durante la operación y registrar información relacionada con el kilometraje y los abastecimientos de combustible. De esta manera, el conductor proporciona información operativa que posteriormente puede ser consultada por el jefe de flota para realizar el seguimiento de los vehículos.
</p>

<p style="text-align: justify;">
  Desde una perspectiva conductual, el conductor prioriza la rapidez y facilidad de uso, debido a que el registro de información forma parte de una jornada principalmente operativa y no debería representar una carga administrativa adicional. Por ello, FleetCare debe reducir la cantidad de pasos necesarios para completar las operaciones frecuentes y facilitar acciones como completar una inspección, registrar el kilometraje, registrar un abastecimiento de combustible o reportar una incidencia con evidencia fotográfica.
</p>

<p style="text-align: justify;">
  En cuanto a su perfil tecnológico, el conductor utiliza principalmente dispositivos móviles durante sus actividades diarias, debido a que gran parte de sus interacciones con FleetCare pueden realizarse antes, durante o después de la operación del vehículo. Por esta razón, la interfaz debe adaptarse a diferentes tamaños de pantalla y permitir que las principales operaciones de registro puedan realizarse de manera sencilla desde un navegador web.
</p>

### **2.1.2. Strategies and Tactics Against Competitors**

**Offensive Strategies**

<p style="text-align: justify;">
  <i>Penetración mediante especialización y accesibilidad</i><br>
  Aprovechando el enfoque de FleetCare en pequeñas empresas de transporte y logística, la estrategia ofensiva se orientará a ofrecer una solución SaaS accesible y enfocada en las necesidades operativas de este segmento. Mientras otras alternativas pueden incorporar funcionalidades complejas o estar orientadas a flotas de mayor tamaño, FleetCare buscará facilitar la gestión de vehículos, mantenimientos, inspecciones, incidencias, kilometraje y combustible desde una plataforma centralizada. La táctica será ofrecer una solución sencilla de adoptar que permita a estas empresas digitalizar progresivamente la gestión de su flota sin requerir infraestructura tecnológica compleja.
</p>

**Adaptive Strategies**

<p style="text-align: justify;">
  <i>Adaptación a las necesidades operativas de pequeñas flotas</i><br>
  Para enfrentar la baja presencia inicial de la marca y adaptarse a un mercado donde muchas pequeñas empresas todavía gestionan sus vehículos mediante registros manuales o herramientas dispersas, FleetCare buscará acercarse directamente a empresas de transporte y logística para comprender sus procesos y validar la solución. La táctica será realizar pruebas piloto con potenciales usuarios, recopilar retroalimentación y ajustar progresivamente las funcionalidades de la plataforma de acuerdo con las necesidades identificadas, priorizando aquellas relacionadas con mantenimiento preventivo, inspecciones y control operativo de los vehículos.
</p>

**Defensive Strategies**

<p style="text-align: justify;">
  <i>Diferenciación mediante facilidad de uso y enfoque en la gestión preventiva</i><br>
  Frente a competidores con mayor reconocimiento o plataformas de gestión de flotas con un alcance funcional más amplio, FleetCare buscará diferenciarse mediante una experiencia sencilla y orientada a las actividades cotidianas de pequeñas flotas. La táctica será mantener procesos claros para registrar vehículos, realizar inspecciones preoperacionales, reportar incidencias, programar mantenimientos y registrar kilometraje y combustible. De esta manera, la facilidad de uso y el enfoque en la prevención de fallas se convierten en elementos de diferenciación frente a soluciones más complejas.
</p>

**Survival Strategies**<br>

<p style="text-align: justify;">
  <i>Validación temprana y desarrollo progresivo del producto</i><br>
  La combinación de ser una solución nueva y competir con herramientas ya establecidas representa uno de los principales riesgos para FleetCare. Para reducir este riesgo, la estrategia será validar tempranamente la propuesta con pequeñas empresas de transporte y logística antes de ampliar significativamente el alcance del producto. La táctica será desarrollar inicialmente las funcionalidades principales, realizar pruebas con usuarios potenciales y utilizar la información obtenida para mejorar la plataforma de manera progresiva. Esto permitirá concentrar los recursos en necesidades reales del mercado y generar evidencia sobre la utilidad de FleetCare antes de realizar una expansión mayor.
</p>

    <tr>
      <td style="text-align: center;">Mantenimiento Preventivo</td>
      <td style="text-align: justify;">Mantenimiento programado de acuerdo con criterios como kilometraje o fecha, realizado para conservar el vehículo en condiciones adecuadas de operación y reducir la posibilidad de fallas.</td>
    </tr>
    <tr>
      <td style="text-align: center;">Mantenimiento Correctivo</td>

      <td style="text-align: center;">Registro de Mantenimiento</td>

## **4.2. Information Architecture**

### **4.2.1. Organization Systems**

<p style="text-align: justify;">
  La arquitectura de información de FleetCare sigue una <b>organización jerárquica</b> complementada con una <b>navegación basada en tareas</b>. La información se estructura de acuerdo con los principales dominios funcionales de la plataforma: Fleet Management, Inspection Management, Incident Management, Maintenance Management y Vehicle Operations Management. Adicionalmente, User Access and Roles proporciona capacidades compartidas relacionadas con autenticación, usuarios y permisos, mientras que el Dashboard funciona como una vista transversal que consolida información proveniente de los diferentes Bounded Contexts.
</p>

**Primary Organization Structure:**

**I. Hierarchical Organization (Main Structure)**

```text
FleetCare Platform
│
├── Dashboard
│   └── Fleet Overview
│
├── Fleet Management
│   ├── Vehicles
│   ├── Vehicle Details
│   └── Operational Status
│
├── Inspection Management
│   ├── Pre-operational Inspections
│   ├── Checklists
│   ├── Inspection Details
│   └── Inspection History
│
├── Incident Management
│   ├── Report Incident
│   ├── Active Incidents
│   ├── Incident Details
│   └── Incident History
│
├── Maintenance Management
│   ├── Scheduled Maintenance
│   ├── Upcoming Maintenance
│   ├── Overdue Maintenance
│   ├── Maintenance Details
│   └── Maintenance History
│
├── Vehicle Operations Management
│   ├── Mileage
│   │   ├── Mileage Records
│   │   └── Distance Traveled
│   │
│   └── Fuel
│       ├── Fuel Records
│       ├── Fuel Consumption
│       ├── Fuel Expenses
│       └── Fuel Efficiency
│
└── User Access and Roles
    ├── Account Access
    ├── User Profile
    ├── Fleet Members
    └── Roles & Permissions
```

<p style="text-align: justify;">
  Esta estructura mantiene una correspondencia directa con los cinco Bounded Contexts principales de FleetCare. Dashboard se ubica fuera de ellos debido a que funciona como una composición transversal de información y no administra información de dominio propia. De manera similar, User Access and Roles se considera una capacidad compartida de soporte y no un Bounded Context principal.
</p>

<div style="page-break-after: always;"></div>

**II. Chronological Organization**

<p style="text-align: justify;">
  La organización cronológica se aplica a la información cuya evolución depende del tiempo y que requiere ser consultada de acuerdo con la fecha en que fue registrada, programada o completada.
</p>

- **Inspections:** Las inspecciones pueden ordenarse desde las más recientes y consultarse considerando su fecha y el vehículo asociado.

- **Incidents:** Las incidencias se organizan cronológicamente para facilitar la consulta de los problemas reportados y su evolución hasta la resolución.

- **Maintenance Records:** Los mantenimientos se organizan considerando la fecha programada, la fecha de realización y, cuando corresponda, el kilometraje objetivo.

- **Mileage Records:** Los registros de kilometraje se organizan cronológicamente para consultar la evolución del uso y la distancia recorrida por cada vehículo.

- **Fuel Records:** Los abastecimientos de combustible se organizan cronológicamente para consultar el historial de consumo y gasto asociado a cada vehículo.

<div style="page-break-after: always;"></div>

**III. Sequential Organization**

<p style="text-align: justify;">
  La organización secuencial se utiliza en los procesos donde el usuario debe realizar diferentes actividades siguiendo un orden lógico hasta completar una operación.
</p>

- **Pre-operational Inspection:** Seleccionar vehículo → Iniciar inspección → Completar checklist → Registrar observaciones o evidencia → Finalizar inspección.

- **Incident Management:** Reportar incidencia → Adjuntar evidencia y ubicación → Consultar incidencia → Actualizar estado → Registrar resolución.

- **Maintenance Management:** Programar mantenimiento por fecha o kilometraje → Identificar mantenimiento próximo o vencido → Realizar mantenimiento → Registrar trabajos, repuestos y costo → Consultar registro de mantenimiento.

- **Vehicle Registration:** Registrar vehículo → Validar información → Incorporar vehículo a la flota → Consultar información registrada.

- **Mileage Registration:** Seleccionar vehículo → Registrar kilometraje → Validar información → Incorporar registro al historial del vehículo.

- **Fuel Registration:** Seleccionar vehículo → Registrar abastecimiento → Registrar cantidad y costo → Incorporar registro al historial de combustible.

- **Account Recovery:** Solicitar recuperación de contraseña → Acceder al mecanismo de recuperación → Restablecer contraseña → Iniciar sesión.

<div style="page-break-after: always;"></div>

**IV. Topic-Based Organization**

<p style="text-align: justify;">
  El contenido de FleetCare se agrupa de acuerdo con los principales dominios funcionales definidos para la plataforma. Esta organización permite mantener una separación clara de responsabilidades y facilita que cada módulo evolucione de manera independiente.
</p>

- **Fleet Management:** Comprende el registro, consulta y actualización de vehículos, su información técnica, estado operativo, búsqueda por placa y filtrado dentro de la flota.

- **Inspection Management:** Comprende las inspecciones preoperacionales, checklists, observaciones, evidencias, resultados e historial de inspecciones realizadas sobre los vehículos.

- **Incident Management:** Comprende el reporte de incidencias, evidencias, ubicación, consulta de incidencias activas, seguimiento de estados, resolución e historial de incidencias.

- **Maintenance Management:** Comprende la programación de mantenimientos por fecha o kilometraje, identificación de mantenimientos próximos o vencidos, registro de intervenciones, trabajos realizados, repuestos utilizados, costos e historial de mantenimiento.

- **Vehicle Operations Management:** Comprende el registro y consulta del kilometraje y los abastecimientos de combustible, así como el análisis de distancia recorrida, consumo, gasto y rendimiento de combustible.

- **User Access and Roles:** Comprende el registro y autenticación de usuarios, recuperación y restablecimiento de contraseña, gestión de sesiones, incorporación de miembros de la flota y control de acceso según el rol.

<p style="text-align: justify;">
  Dashboard complementa esta organización presentando información resumida proveniente de los diferentes dominios. Su función es facilitar la consulta general del estado y operación de la flota, sin convertirse en propietario de los datos presentados.
</p>

<div style="page-break-after: always;"></div>

**Content Categorization:**

**By User Role:**

- **Fleet Manager:** Accede al Dashboard y administra principalmente las funcionalidades relacionadas con Fleet Management. También consulta inspecciones, realiza seguimiento de incidencias, programa y supervisa mantenimientos, consulta información de Vehicle Operations Management y administra los miembros de la flota.

- **Driver:** Accede principalmente a Inspection Management para realizar inspecciones preoperacionales, a Incident Management para reportar incidencias y a Vehicle Operations Management para registrar kilometraje y abastecimientos de combustible.

- **Mechanic:** Accede principalmente a Maintenance Management para consultar mantenimientos y registrar las intervenciones realizadas, incluyendo trabajos efectuados, repuestos utilizados y demás información correspondiente al mantenimiento.

- **Visitor:** Accede a la Landing Page para conocer la propuesta de FleetCare y utilizar las opciones disponibles para registrarse o acceder a la plataforma.

<p style="text-align: justify;">
  Las funcionalidades visibles para cada usuario dependen de su rol y permisos. La inclusión de Mechanic como rol funcional no modifica la definición de Fleet Manager y Driver como los dos segmentos principales utilizados en el Impact Mapping.
</p>

**By Priority:**

- **Critical:** Vehículos fuera de servicio, incidencias activas de alta severidad y mantenimientos vencidos que requieren atención prioritaria.

- **High:** Vehículos que requieren atención, incidencias activas, mantenimientos próximos e inspecciones que presentan elementos no conformes.

- **Medium:** Registros recientes de kilometraje, abastecimientos de combustible, inspecciones completadas y mantenimientos realizados utilizados para el seguimiento operativo.

- **Low:** Información histórica, incidencias resueltas y registros anteriores utilizados principalmente para consulta y análisis.

### **4.2.4. Searching Systems**

<p style="text-align: justify;">
  FleetCare implementa mecanismos de búsqueda y filtrado orientados a facilitar la localización de vehículos y registros asociados a los diferentes Bounded Contexts. El alcance de los resultados depende del rol y de los permisos del usuario, manteniendo la separación funcional entre Fleet Management, Inspection Management, Incident Management, Maintenance Management y Vehicle Operations Management.
</p>

**Global Search (Header)**

- **Location:** Barra superior de navegación, disponible en las principales vistas de la aplicación.

- **Scope:** Realiza búsquedas sobre la información accesible para el usuario según su rol y permisos.

- **Input:** Campo de texto con icono de búsqueda y placeholder: `"Buscar vehículos, inspecciones, incidencias..."`.

- **Minimum Characters:** 2 caracteres para iniciar la búsqueda.

- **Debounce Delay:** 300ms para evitar solicitudes innecesarias mientras el usuario escribe.

**Features:**

- **Real-time suggestions:** Presenta sugerencias mientras el usuario ingresa el término de búsqueda.

- **Search categories:** Vehicles, Inspections, Incidents y Maintenance.

- **Recent searches:** Puede mostrar las últimas búsquedas realizadas durante la sesión del usuario.

- **Keyboard shortcut:** `Cmd/Ctrl + K` permite enfocar el campo de búsqueda desde Desktop.

- **Clear button:** El icono `X` permite limpiar el término ingresado y los resultados mostrados.

<p style="text-align: justify;">
  La búsqueda global funciona como un mecanismo transversal de consulta y no constituye un Bounded Context independiente. Cada resultado mantiene una referencia al módulo responsable de la información encontrada.
</p>

**Search Results Display:**

**Search Algorithms & Behavior:**

<p style="text-align: justify;">
  FleetCare utiliza mecanismos de búsqueda de diferente nivel de precisión según el tipo de información consultada. Las capacidades más avanzadas pueden incorporarse progresivamente de acuerdo con las necesidades del producto.
</p>

**I. Exact Match (Highest Priority):**

- Vehicle IDs.
- License Plates.
- Inspection IDs.
- Incident IDs.
- Maintenance IDs.
- Mileage Record IDs.
- Fuel Record IDs.

- **Pattern:** Comparación exacta sin diferenciar entre mayúsculas y minúsculas cuando corresponda.

**II. Prefix Match:**

- License Plates.
- Vehicle Brand and Model.
- Record identifiers.

- Utilizado principalmente para proporcionar sugerencias mientras el usuario escribe.

- **Pattern:** `query*`

**III. Full-Text Search:**

- Incident descriptions.
- Inspection observations.
- Maintenance descriptions or work performed.

- Permite localizar registros que contienen el término ingresado dentro de campos descriptivos.

- Esta capacidad puede utilizar campos indexados para mejorar el rendimiento cuando el volumen de información lo requiera.

**IV. Fuzzy Match (Optional):**

- Puede aplicarse a determinados campos textuales para tolerar errores menores de escritura.

- Se considera una capacidad complementaria y no es necesaria para el funcionamiento inicial de FleetCare.

- Ejemplo: `"Toyta"` → `"Toyota"`.

**V. Filter-Based Search:**

- Permite combinar criterios específicos como estado, fecha, vehículo o tipo de registro.

- Los filtros de un mismo módulo pueden combinarse mediante lógica `AND` cuando todas las condiciones seleccionadas deben cumplirse.

- Los filtros disponibles dependen del Bounded Context consultado.

<div style="page-break-after: always;"></div>

**Search Performance Optimizations:**

**Pagination:**

- **Default:** 25 resultados por página.

- **Options:** 10, 25, 50.

- En dispositivos móviles puede utilizarse una acción **Load More** cuando resulte conveniente para la experiencia de navegación.

**Sorting Options:**

- Relevance para búsquedas textuales.

- Date (newest/oldest).

- Name (A-Z, Z-A) cuando corresponda.

- Status en módulos que administran estados.

- Mileage para registros operativos y de mantenimiento.

- Cost para registros donde esta información se encuentre disponible.

**Caching:**

- Las búsquedas recientes pueden conservarse temporalmente durante la sesión.

- Los filtros pueden mantenerse mientras el usuario navega dentro del mismo módulo.

**Indexing:**

- Los campos utilizados frecuentemente para búsquedas exactas, como identificadores y placas, pueden utilizar índices en la base de datos.

- Los campos empleados habitualmente como filtros pueden ser indexados cuando el volumen de información y las necesidades de rendimiento lo justifiquen.

- Las capacidades de búsqueda textual avanzada pueden incorporarse progresivamente sin modificar la responsabilidad de los Bounded Contexts.

```text
Home > ... > Vehicle > Current
```

**4. Browser Integration:**

- **Back Button:** Permite regresar a la página anterior.

- **Forward Button:** Permite avanzar nuevamente dentro del historial de navegación.

- **Deep Linking:** Las principales vistas cuentan con rutas específicas.

- **Bookmarking:** Las rutas pueden almacenarse cuando la vista y los permisos del usuario lo permitan.

```text
/dashboard

/vehicles
/vehicles/:id

/inspections
/inspections/:id

/incidents
/incidents/:id

/maintenance
/maintenance/:id

/operations/mileage

/users
/profile
```

<p style="text-align: justify;">

</p>

**5. State Preservation:**

- **Filter State:** Los filtros pueden mantenerse mediante parámetros de consulta cuando resulte conveniente.

- **Scroll Position:** Puede restaurarse al regresar a determinadas vistas.

- **Form Data:** Los formularios extensos pueden conservar temporalmente información no enviada cuando esta característica sea implementada.

- **Session:** La sesión permanece disponible de acuerdo con las políticas de autenticación definidas para FleetCare.

- **Focus Indicators:** Los componentes interactivos muestran visualmente cuándo reciben el foco.

- **Logical Order:** El orden de navegación sigue la jerarquía visual de la página.

**2. ARIA Landmarks:**

```html
<nav aria-label="Main Navigation">...</nav>

<main>...</main>

<aside aria-label="Filters">...</aside>
```

**3. Screen Reader Support:**

**4. Focus Management:**

- **Form Submission:** Después del envío de un formulario, el foco puede dirigirse al mensaje de confirmación o al primer campo que contenga un error.

**5. Touch Targets (Mobile):**

- **Spacing:** Se mantiene una separación suficiente entre las acciones táctiles.

- **Tap Feedback:** Los elementos proporcionan una respuesta visual al ser seleccionados.

### **5.1.3. Source Code Style Guide & Conventions**

<p style="text-align: justify;">
  Para mantener consistencia, legibilidad y facilidad de mantenimiento en el código fuente de FleetCare, se establecen convenciones de programación de acuerdo con las tecnologías utilizadas actualmente en el proyecto. Estas convenciones comprenden HTML, CSS y JavaScript para la Landing Page, además de Vue.js y JavaScript para la Web Application.
</p>

**HTML**

- **Standards:**
  - Uso de HTML semántico.
  - Indentación de 2 espacios.
  - Uso de comillas dobles para atributos.
  - Nombres descriptivos para identificadores y clases.
  - Uso apropiado de elementos como `<header>`, `<nav>`, `<main>`, `<section>`, `<article>` y `<footer>`.

**Example:**

```html
<section class="features">
  <h2>Fleet Management</h2>
  <p>Manage your fleet information from one place.</p>
</section>
```

**CSS**

- **Conventions:**
  - Indentación de 2 espacios.
  - Nombres de clases descriptivos.
  - Reutilización de estilos comunes.
  - Organización de estilos por componentes o secciones.
  - Uso de Media Queries para adaptar la interfaz a diferentes tamaños de pantalla.
  - Uso consistente de la paleta de colores y variables visuales definidas para FleetCare.

**Example:**

```css
.vehicle-card {
  display: flex;
  padding: 1rem;
  border-radius: 0.5rem;
}

@media (max-width: 768px) {
  .vehicle-card {
    flex-direction: column;
  }
}
```

**JavaScript**

- **Guidelines:**
  - Variables y funciones utilizando `camelCase`.
  - Uso de `const` como opción principal y `let` cuando el valor debe modificarse.
  - Se evita el uso de `var`.
  - Funciones y variables con nombres descriptivos.
  - Separación de responsabilidades entre funciones.
  - Uso de funciones flecha cuando resulte apropiado.

**Example:**

```javascript
const showVehicleDetails = (vehicleId) => {
  // Display the selected vehicle information
};
```
